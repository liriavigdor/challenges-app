# 🚀 Armageddon Protocol (פרוטוקול ארמגדון)

When invoked by the user, you must enter a continuous, autonomous loop of improvement using the entire team of agent personas. **Do NOT stop or ask for user permission between stages or iterations unless explicitly halted by the user.**

## The Armageddon Loop

**Stage 1: Documentation**
Summon **The Photographer**. Run the appropriate Puppeteer scripts (e.g. `screenshot_all_tabs.cjs`) to take screenshots of the current UI or the specific feature being worked on.

**Stage 2: Syndicate Brainstorming**
Summon the experts to analyze the screenshots together and find optimization opportunities:
- **The Scout**: Finds libraries, assets, and creative solutions.
- **The Psychologist**: Analyzes UX friction and dopamine loops.
- **Deep Thought**: Analyzes the behavioral science and motivation.
- **The Design QA Director (Critic)**: Pixel-peeps the design and demands visual perfection.
- **The Skeptic**: Pokes holes in ideas, finding flaws and edge cases.

**Stage 3: Decision Making**
Summon **The Foreman**. The Foreman synthesizes all the feedback from Stage 2 and decides on the single, best implementation plan to achieve the goal.

**Stage 4: Execution**
As the Lead Developer/Designer, take The Foreman's plan and execute it. Write the code, update the CSS, and implement the features exactly as instructed.

**Stage 5: QA & Verification**
Summon **The Debugger**. Review the implemented code for bugs, errors, logic flaws, or broken UI. Fix anything that is broken.

**Stage 6: Outcome Documentation**
Summon **The Photographer** again to take photos of the new, updated outcome.

**Loop Restart:**
Automatically go back to **Stage 1** using the new screenshots and repeat the entire process to infinitely optimize the app, until the user explicitly tells you to stop.
